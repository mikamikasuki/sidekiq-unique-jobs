# Workflow profile

Everything the shared workflow skills (`/lode:lfg`, `/lode:review-pr`,
`/lode:finish-prs`, `/lode:debug-flaky`, `/lode:tdd`, `/lode:plan`) need to know
about this repository that is not already in `../CLAUDE.md`, `../.claude/rules/`
or the rest of `lode/`.

## Commands

Everything below runs from the repo root unless the row says otherwise.
**Anything that touches `spec/` needs a Redis on `localhost:6379`** — the suite
flushes the database before and after every example, so never point it at a
Redis holding anything you care about.

| Purpose | Command | Notes |
|---|---|---|
| fast loop (one file) | `bundle exec rspec <file>` (or `<file>:<line>`) | needs Redis; `bin/rspec` is the binstub CI uses |
| full suite | `bundle exec rspec --tag ~perf` | needs Redis, no other service, no network. **Not safe in two worktrees at once** — both would flush the same database |
| benchmarks only | `bundle exec rspec spec/performance --tag perf` | `spec/support/rspec_benchmark.rb` calls `filter_run_excluding perf: true`, so these never run unless you ask for the tag |
| lint | `bundle exec rubocop -P` (`bin/rubocop -P` is what CI runs) | `bundle exec rake style` also runs a Reek stub that does nothing — see `review/tooling-and-release.md` |
| one CI cell locally | `BUNDLE_GEMFILE=gemfiles/sidekiq_8.1.gemfile bundle exec rspec --tag ~perf` | `bundle exec appraisal …` is documented in `CLAUDE.md` but currently raises a `SyntaxError` parsing the root `Gemfile`'s `install_if` block; set `BUNDLE_GEMFILE` directly instead |
| docs build / check | `cd docs && bundle exec rake lint && bundle exec rspec` | separate bundle; `rake lint` passes an explicit file list because the root `.rubocop.yml` excludes `docs/**` |
| docs locally | `cd docs && bin/dev` | |
| run the app | `cd myapp && bin/dev` | localhost-only harness: Rails on 3000, a CSS watcher and eight Sidekiq processes |
| CLI | `bundle exec bin/uniquejobs help` | `list`, `del`, `console` |
| gem contents | `bundle exec rake build` | builds and unpacks so you can see what ships |

## Branches and PRs

- Default branch: `main`. CI also runs on `v9`.
- Work branches: `feature/*`, `fix/*`, `refactor/*`, `perf/*`, `chore/*`, rooted
  off fresh `origin/main` (`../.claude/rules/git-workflow.md`).
- Commits: conventional (`feat:`, `fix:`, `refactor:`, `perf:`, `docs:`,
  `test:`, `chore:`); the body says why, not what.
- PR body sections, in order: Summary, Test plan, Deviations & judgment calls,
  Gate.
- Merge policy: squash onto `main` after green and approval; never force-push a
  published branch, never commit to `main` directly.
- Attribution: no `Co-Authored-By: Claude` and no "Generated with" lines. End a
  commit message with the `Claude-Session:` line and a PR body with the session
  URL when the harness supplies one.

## Shapes

Check a change against these before calling it done.

- **Lock types:** all fourteen aliases, but especially the three that behave
  unlike the rest — `until_expired` (never unlocks; `unlock.lua` returns early),
  `while_executing*` (locks on the `:RUN` digest, no client lock), and
  `until_and_while_executing` (two locks, a `WhileExecuting` built from
  `item.dup`).
- **`lock_limit > 1`:** the LOCKED hash has several fields; `Lock#info` and the
  detail page show only the first.
- **A digest carrying the `:RUN` suffix:** the reaper strips it on both sides
  before matching, and `UpgradeLocks` deletes the `:RUN` variants too.
- **A job hash with no `lock` option, and `config.enabled = false`:** both must
  bypass the gem entirely through `unique_disabled?`.
- **Deprecated keys:** `unique`, `unique_args`, `lock_args`, `unique_prefix`,
  `unique_args_method`, `lock_expiration` — still read, still reported by the
  validator.
- **A payload that will not parse:** `fetch.lua`, `Orphans::Reaper#active?`,
  `Fetch::Reliable#recover_orphans`, `Lock#build_info` and
  `Helpers#display_lock_args` each meet one and must not raise.
- **Redis mid-iteration:** an empty `SCAN` page with a non-zero cursor, and a
  queue shrinking under an `LRANGE` window.
- **Both middleware chains:** the digest is recomputed on each, so a change to
  `Job.prepare` has to hold for a client push and a server perform.
- **Sidekiq 8.0 and 8.1, Ruby 3.2 through 4.0** — the gemspec floor is Ruby
  3.2.0, so no syntax newer than that.
- **A process that cannot reach Redis:** `Server`'s background work and the
  metrics writers must log and continue.

## Constraints

Suggestions that are wrong in this repository. `/lode:review-pr` pushes back on
these on sight.

| Suggestion | Why it is wrong here |
|---|---|
| "`Locksmith#execute` should unlock in an `ensure`" | it would release the lock when a job raises, and `until_executed` deliberately holds it through the retry (`review/lock-model.md`) |
| "use the `Redis::List`/`Redis::SortedSet` wrappers in the reaper" | each wrapper opens its own connection; the reaper must stay on the one it was handed (`review/orphans-and-fetch.md`) |
| "break out of the SCAN loop when the batch is empty" | Redis returns empty pages mid-iteration; only the cursor ends a scan |
| "make the reaper delete when it cannot confirm the job exists" | inverted; every uncertain predicate answers "keep" |
| "narrow the `sidekiq` dependency to the tested versions" | the matrix tests released versions; the bound excludes Sidekiq 10 (`review/lock-model.md`) |
| "add `enabled: false` to these `use_config` blocks" | only for specs unrelated to uniqueness; the config and conflict specs are *about* it (`review/myapp.md`) |
| "add CSRF protection / authentication to `myapp`" | localhost-only development harness, never deployed (`review/myapp.md`) |
| "freeze time in the metrics specs" | the bucket arithmetic is the thing under test (`review/web-and-metrics.md`) |
| "fix the stale locks in `bin/benchmark*`" | throwaway harnesses that flush Redis between sections |
| "edit `CHANGELOG.md`" | generated by `rake changelog` |

## Docs

- User-facing docs live in `docs/app/views/docs/pages/` — 26 `DocsUI::Page`
  subclasses, registered in `docs/app/models/doc.rb`, published to
  https://sidekiq-unique-jobs.zoolutions.llc. Add one with
  `cd docs && bin/rails g docs_kit:page "Title" --group=…`; the authoring
  contract is `docs/AGENTS.md`.
- A page maps to a behaviour by name: a lock-type change touches
  `choosing_a_lock_type.rb`, `lock_lifecycle.rb` and the matching recipe page
  (`process_exactly_once.rb`, `one_per_period.rb`, …); a config key touches
  `configuration_reference.rb` and `worker_options.rb`; a reflection touches
  `reflections.rb` and `observability.rb`; reaper or fetch work touches
  `orphaned_locks_and_recovery.rb` and `reliablefetch.rb`; a v9 behaviour change
  touches `upgrading_to_v9.rb`.
- `README.md` and `UPGRADING.md` at the root cover the same ground for people
  who never open the site — a fact stated in one has to agree with the other.
- Changelog: `CHANGELOG.md`, **generated** by `bundle exec rake changelog`
  (github_changelog_generator, needs `CHANGELOG_GITHUB_TOKEN`). Put the prose a
  reader needs in the PR title and body, because that is what ends up there.
- Files that pin a version and drift after a release: none in the gem;
  `docs/Gemfile.lock` and `docs/bun.lock` are regenerated with
  `cd docs && bundle install` / `bun install`.

## CI

- Workflows: `rspec.yml` (the suite; `pull_request` and pushes to `main`/`v9`),
  `lint.yml` (RuboCop on Ruby 3.2, same triggers), `docs-ci.yml` (only when
  `docs/**` changes), `release.yml` (on a published release: RuboCop → the
  suite → build → verify contents → checksums → Sigstore → RubyGems trusted
  publishing → upload assets), `deploy-docs.yml` (on a published release).
- Matrix: `rspec.yml` runs Ruby 3.2, 3.3, 3.4 and 4.0. Services are a Redis and
  a toxiproxy container, and the run exports `REDIS_HOST=localhost`,
  `TOXI_REDIS_URL=toxiproxy:21212`, `TOXI_PROXY_HOST=http://toxiproxy:8474`.
  The one spec that uses toxiproxy — `spec/integration/until_and_while_executing_spec.rb`
  — is wrapped in `unless ENV.fetch("CI", false)`, so it runs **locally and not
  in CI**: those variables are exported for a file CI skips, and locally you
  need a toxiproxy on `localhost:21212` / `http://127.0.0.1:8474` or that file
  errors.
- Fetch a failure: `gh run view --job <id> --log-failed`.
- "Green" means every `rspec` matrix cell plus `rubocop`, and `docs` too when
  the PR touches `docs/**`.
- Known not-this-branch noise: the `gemfile` matrix dimension in `rspec.yml` is
  declared but never applied (no step sets `BUNDLE_GEMFILE`), so both values run
  the same bundle and a per-Sidekiq-version failure cannot appear there; the
  `coverage` job checks out and installs Ruby without running anything.
- Shared or rate-limited services the checks hit: none — each job gets its own
  Redis container.

## Flake sources

- **A shared Redis.** Every example flushes the database; two suites against one
  server destroy each other's state. One runner at a time, and never against a
  Redis you use for anything else.
- **The local-only toxiproxy spec.** `spec/integration/until_and_while_executing_spec.rb`
  runs only when `CI` is unset and needs a toxiproxy container; `CI=1` is the
  documented way to skip it.
- **Wall-clock windows.** `LockMetrics` buckets by the current UTC minute and
  `query`/`by_type` read the last N; an example that flushes at :59.9 and reads
  at :00.1 can miss its own write. The reaper's `GRACE_PERIOD` (10s),
  `reaper_timeout` budget and `max_score` window are the same kind of edge.
- **Background threads.** `Fetch::Reliable`'s heartbeat thread and the three
  `TimerTask`s in `Server` outlive an example unless it stops them; the tasks
  are created with `run_now: false`, so a test that expects one to have fired
  must trigger it.
- **`config.order = :random`** with a seeded `Kernel.srand`: a failure is
  reproducible with the printed seed, so capture it before doing anything else.
- **Class-level state.** `Server`'s `@reaper_task`/`@metrics`,
  `Script::Scripts::SCRIPT_PATHS`, and `SidekiqUniqueJobs.config` all persist
  across examples; `use_config` and the shared contexts exist because assigning
  them directly leaks.

## Conflicts

| File | Rule |
|---|---|
| `Gemfile.lock`, `gemfiles/*.lock` | not tracked (`.gitignore`) — nothing to merge |
| `docs/Gemfile.lock`, `docs/bun.lock`, `myapp/Gemfile.lock`, `myapp/bun.lock` | the tracked lockfiles; never hand-merge: take the base's, then re-resolve in that directory (`bundle install` for a Gemfile.lock, `bun install` for a bun.lock) |
| `CHANGELOG.md` | generated: take the base's and re-run `rake changelog` rather than merging hunks |
| `lib/sidekiq_unique_jobs/version.rb` | take the base's; a version bump belongs to the release, not to a feature branch |
| `lib/sidekiq_unique_jobs/config.rb` | append-only, base order first: the struct members, the default constants and the `Config.default` arguments are three parallel lists and must stay aligned |
| `lib/sidekiq_unique_jobs/constants.rb`, `reflections.rb` (`REFLECTIONS`) | union, base order first; these are alphabetical lists |
| `spec/support/workers/*.rb` | add a new worker rather than merging two option sets into one fixture |
| `gemfiles/*.gemfile` | committed source: merge both sides' intent by hand. Regenerating from `Appraisals` is the eventual answer, but `bundle exec appraisal` currently fails on the root `Gemfile`'s `install_if` block (see Commands), so do not rely on it |
| `lib/sidekiq_unique_jobs/lua/**` | merge as source, then prove it: `bundle exec rspec spec/sidekiq_unique_jobs/script spec/sidekiq_unique_jobs/lock --tag ~perf` (needs Redis) |

## Verification

- The manual check a user of a lock change would do: `cd myapp && bin/dev`, open
  http://localhost:3000/locks, enqueue one of the nine `DEMO_JOBS` a few times,
  and watch the digest appear in the Locks tab and disappear when the job
  finishes. The metrics panel above the table shows Acquired / Denied /
  Released / Failures for the last hour.
- The check for a reaper change: leave a digest behind (enqueue, then flush the
  queue), wait past `GRACE_PERIOD` and call `SidekiqUniqueJobs::Server.reap`,
  which returns the number removed.
- Stress iterations for a flake proof: 50 runs of the single example, or
  `--seed` sweeps of the file, before calling a race fixed.
- Where evidence goes: `lode/tmp/` (git-ignored) unless the PR needs an
  auditable trail.
